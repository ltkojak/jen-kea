{{ icon("wrench", "ico-lg") }} Kea reservation identifiers

Finds and repairs reservations whose identifier was stored as text by an older Jen restore or migration. Nothing changes until you press Repair.

What this looks for

Before 5.67.0-beta.11, restoring a Kea backup or import file, or migrating the Kea database, wrote a reservation's identifier as the text of its own hex: the six-byte MAC 34:13:43:e6:0e:2a became the twelve characters 341343e60e2a. The row looks right but Kea never matches the client to it again.

Only hosts.dhcp_identifier of type hw-address, DUID or client-id is recognised, and only when it is an even number of hex-digit characters of a plausible length. Circuit-id and flex-id are never flagged — ASCII hex is legitimate there. Per-host option values cannot be told from intended ones and are not touched; check them by hand after a restore made before this release. Only the hosts table changes, only the identifier column, only rows listed below that still hold exactly what is shown.
